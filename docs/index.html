ONE PLACE FOR PROJECT COMMANDS

Your project, ready to run.

runui finds the tasks, scripts, targets, services, and builds in a folder. Pick one, watch its output, and close the interface whenever you like. The command keeps running until you stop it.

Start using runui → See how a run works
5 project file types 3 panels 1 persistent run history
01

GET MOVING

Quick start

Build from this repository with Rust 1.88 or newer on macOS or Linux. Task is the shortest route; Cargo works directly too.

With Task
task install

Installs to ~/.local/bin.

With Cargo
cargo install --path crates/runui --root ~/.local --locked

Put ~/.local/bin on your PATH.

Try it in a project
$ runui
$ runui -C ~/projects/atlas
$ runui list
$ runui ps

runui discovers commands; the corresponding tool must be installed to run one. For example, a Taskfile task needs task, and a Compose service needs Docker Compose.

02

THE CORE LOOP

A run, start to finish

1

Find it

Choose a row in Project, or press / and filter by its name, folder, command, or description.

2

Run it

Press enter. The command starts in the folder where its project file lives, and its output appears in the right pane.

3

Leave it

Press q or close the terminal. A separate supervisor keeps the command running and saves what it prints.

4

Come back

Open runui again. Select the run to read its output, press s to stop it, or R to run it again.

03

DISCOVERY

Commands already in your project

runui starts at the nearest project folder above your current directory, stopping at the repository root. It reads that folder and folders under it three levels deep. A command from apps/web is labeled with that path and runs there.

01 / TASK

Taskfile

Tasks and included tasks, using their names and descriptions. Internal tasks stay out of the list.

task 'docs:serve'
02 / PACKAGE

package.json

Scripts through pnpm, yarn, bun, or npm, as the package manager field or nearest lock file selects.

pnpm run dev
03 / MAKE

Makefile

Targets with their ## comments shown beside them.

make test
04 / CONTAINERS

Compose

Start all services, rebuild, stop, inspect, follow logs, or start a single service.

docker compose up
05 / JAVA

Maven

Install, verify, test, and profile builds. Uses the project's mvnw when it has one.

./mvnw clean verify
When files change

runui notices edits to files it reads. Press r to scan again, including newly added files in nested folders.

04

MAKE IT YOURS

Favorites and your own commands

Press m on a project command to keep it in this folder's Favorites panel. Press a to add a named command of your own, entered exactly as you would run it with sh in this folder.

★

Starred commands

Point back to a task, script, target, service, or build. You can remove the star with m.

$

Your commands

Created with a. Edit with e, reorder with < and >, or remove with D.

05

PERSISTENT BY DESIGN

Runs and their output

Every command has its own supervisor and output file. The Runs panel shows runs in this project under Here, with an Everywhere tab for runs from other folders. Selecting a run brings its stored output back into view.

●Running
✓Exited 0
✗Failed
■Stopped
?Lost

Stopping sends SIGTERM to the command's process group, then SIGKILL after five seconds if it is still there. Press D on an ended run to forget it and its output. runui retains up to 40 ended runs across folders.

Keyboard reference

Press ? inside runui for the complete in-app key sheet. The mouse can select rows and scroll output too.

KeysWhat they do
tab / shift+tab, 1–3Switch between Favorites, Project, and Runs.
[ / ]Switch file type or Here / Everywhere tab.
j / k, g / GMove through rows or jump to the first / last row.
/, escFilter the current tab; clear the filter.
enter, s, RRun, stop, or restart; enter on a run focuses its output.
0, esc, + / _Focus output, return to the panel, or give output the full window and restore it.

07

FROM THE SHELL

CLI reference

runui [-C DIR]

Open the interface in the current project or a specified folder. runui -h prints its built-in help.

runui list [-C DIR]

Print this folder's favorites, discovered commands, and runs. This only reads data.

runui ps

Print every run from every folder, with live runs first.

Use task run -- -C DIR while working in this repository to build and launch the local binary with arguments.

08

UNDER THE HOOD

Files and compatibility

Favorites and runs use the same paths and file formats as the original Go app. The Go build can find, follow, and stop a Rust run, and the Rust build can do the same for a Go run.

Favorites~/.config/runui/favorites.jsonor under $XDG_CONFIG_HOME
Runs, metadata & output~/.local/state/runui/runs/or under $XDG_STATE_HOME

A run's folder holds run.json, output.log, and a lock held by its supervisor. The lock tells the next runui whether the run is still alive, even after the first interface exits.

About this port

The Go app remains the behavior specification. PLAN.md records how the Rust port was checked, including byte-for-byte list comparisons and terminal screens compared cell by cell. AGENTS.md maps the workspace's crates to the original packages.
