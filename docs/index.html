01

GET MOVING

Quick start

Install with Homebrew on macOS or Linux, or build a clone of this repository with Rust 1.88 or newer. Runui is one Rust binary; project commands use their own installed tools.

With Homebrew
brew tap lechero/runui https://github.com/lechero/runui.git
brew install lechero/runui/runui

Homebrew builds Runui from source and installs Rust as a build dependency.

From a clone / Task
task install

Installs to ~/.local/bin.

From a clone / Cargo
cargo install --path crates/runui --root ~/.local --locked

Put ~/.local/bin on your PATH.

Try it in a project
$ runui
$ runui -C ~/projects/atlas
$ runui list
$ runui ps

runui discovers commands; the corresponding tool must be installed to run one. For example, a Taskfile task needs task, and a Compose service needs Docker Compose.

02

THE CORE LOOP

A run, start to finish

1

Find it

Choose a row in Project, or press / and filter by its name, folder, command, or description.

2

Run it

Press enter. The command starts in the folder where its project file lives, and its output appears in the right pane.

3

Leave it

Press q or close the terminal. A separate supervisor keeps the command running and saves what it prints.

4

Come back

Open runui again. Select the run to read its output, press s to stop it, or R to run it again.

03

DISCOVERY

Commands already in your project

runui starts at the nearest project folder above your current directory, stopping at the repository root. It reads that folder and folders under it three levels deep. A command from apps/web is labeled with that path and runs there.

01 / TASK

Taskfile

Tasks and included tasks, using their names and descriptions. Internal tasks stay out of the list.

task 'docs:capture'
02 / PACKAGE

package.json

Scripts through pnpm, yarn, bun, or npm, as the package manager field or nearest lock file selects.

pnpm run dev
03 / MAKE

Makefile

Targets with their ## comments shown beside them.

make test
04 / CONTAINERS

Compose

Start all services, rebuild, stop, inspect, follow logs, or start a single service.

docker compose up
05 / JAVA

Maven

Install, verify, test, and profile builds. Uses the project's mvnw when it has one.

./mvnw clean verify
One search across sources

Press ctrl+p to search commands and favorites together. Try source:npm test or dir:apps/web build. The preview shows the exact command, cwd, provenance, and availability; ctrl+v opens scrollable details. enter runs or focuses live output; alt+r starts another. esc restores your panel selection and filter.

tab switches to Recent invocations, retaining exact commands after output pruning. alt+u selects the current definition separately. alt+m stars, ctrl+y copies, ctrl+o opens source, and ctrl+t opens a terminal through tmux or RUNUI_TERMINAL. The current scope is Project. Workspace/registered search, Composer, Cargo, shell recall and presets remain in progress. Catalog reference.

When files change

runui checks changes in the background, including included Taskfiles, new nested command files, parent lockfiles, and Maven wrappers. Press r to force a rescan. Shared Taskfiles appear under every include namespace. Discovery reports skipped includes, unreadable folders, and limits (three levels, 2,000 folders, 150 definition files), while keeping usable commands.

05

PERSISTENT BY DESIGN

Runs and their output

Every command has its own supervisor and output file. The Runs panel shows runs in this project under Here, with an Everywhere tab for runs from other folders. Once an agent has started a run through runui mcp, an Agents tab lists the runs agents started, wherever they are, each with the name its MCP client gave (agentix, claude-code); it goes away when the last of them is forgotten. Selecting a run previews its stored output and acknowledges its finished result; pressing enter focuses the output.

●Running
✓Exited 0
✗Failed
■Stopped
?Lost

Stopping sends SIGTERM to the command's process group, then SIGKILL after five seconds if it is still there. Press D on an ended run to forget it and its output. When starting a run, runui retains the 40 most recent previous ended runs across folders, including repeated commands.

06

A PLACE TO COME BACK TO

Review it. Keep its history.

Press 4 for Log. Results come from every folder, including agent-started work. Each row shows its project folder, outcome, time, and agent when present. The outcome stays visible after review.

•

Unread

Successful, failed, and lost results still counted in tmux. Selecting a row shows its output and clears only that notice. The selected row stays while you read; refreshes leave the next result unread.

↶

All

Every retained finished attempt, including reviewed and stopped runs, newest finish first. Repeated commands keep their own output and review state. Switch tabs with [ / ].

Use / to search by command, folder, result (completed, failed, lost, stopped), or agent. Press R to follow a new attempt in Runs, y to copy its command, or D to forget an ended run and its output.

Review clears a notice, not a run

Any TUI preview of a finished result marks it as reviewed, without focusing the output pane. If a run finishes while visible, it is reviewed then. Deliberately stopped runs do not count as unread. Log → All keeps reviewed output until it is forgotten or pruned.

07

A QUIET SIGNAL

Know what needs a look

Runui counts active, completed, and errored runs across every folder. Put those counts in tmux's status line to see when a command finishes while you work elsewhere.

1 · project ▶ 2 ✗ 1

A count is a notice to check, not a lifetime total. Zero values have no segment; when every count is zero, Runui’s segment disappears. Allow the configured polling interval after viewing output.

01

Running

▶ A command has started or is still active.

02

Needs attention

✓ Exit 0, or ✗ a failure or lost run. Deliberately stopped runs stay out.

03

Seen

Select a result in Log (4) to view its output. Its completion or error count clears; the All tab keeps its output. Running processes remain counted.

Append the segment to your existing tmux right side. Runui formats the colors and hides zero values:

~/.tmux.conf
set -g status-interval 5
set -ag status-right '#(runui status tmux)'

If plain runui status shows counts but tmux stays blank, put the absolute path from command -v runui inside #(...) and reload tmux. Its server can have a different PATH from your shell.

runui status

Print plain counts for scripts and other status bars.

runui status clear

Dismiss every finished result without stopping runs or deleting logs.

Selecting a run, favorite, or project command that shows a finished run's output marks that result as reviewed, without focusing the pane. If a run finishes while its output is visible, Runui acknowledges it automatically. Running processes remain counted.

09

FROM THE SHELL

CLI reference

runui [-C DIR]

Open the interface in the current project or a specified folder. runui -h prints its built-in help.

runui list [-C DIR]

Print this folder's favorites, discovered commands, and runs. This only reads data.

runui commands [-C DIR] [--query TEXT] [--json]

Search the shared catalog; find is equivalent. Use --mode recent for exact invocation recall, --limit and --offset for bounded pages.

runui inspect [-C DIR] ID [--json]

Show a definition's execution context, provenance, availability and fingerprint.

runui run [-C DIR] ID [--fingerprint FP] [--json] [-- ARGS]

Resolve and prepare a current definition, then start its supervisor. Arguments are literal; --var NAME=value supports Task/Make variables and Maven properties.

runui ps

Print every run from every folder, with live runs first.

runui status [clear|tmux]

Print plain counts, dismiss finished results, or print a colored tmux segment with zero values hidden. Counts cover every folder; stopped runs are omitted.

runui mcp [-C DIR]

Serve local MCP tools for discovering commands and managing persistent runs over stdio.

Use task run -- -C DIR while working in this repository to build and launch the local binary with arguments.

10

FOR AGENTS

Runui as an MCP server

Your terminal and agent work on the same processes. Runui’s six local tools discover exact commands, start persistent runs, read output, and stop work. Agent runs appear in Runs → Agents under the client’s name, then in Log when finished. Closing the MCP connection leaves the work running.

  1. 01 / DISCOVERlist_commands

    Choose an exact command and directory.

  2. 02 / STARTstart_run

    Keep the returned run ID.

  3. 03 / FOLLOWget_run · read_output

    Inspect the same state and output as the TUI.

  4. 04 / CONTROLstop_run

    Request a stop, then wait for the final state.

Connect a local client

Start runui mcp -C /absolute/path/to/project from a local MCP client. The client launches runui as a subprocess and exchanges newline-delimited JSON messages over stdin and stdout. There is no network listener. Use the installed binary's absolute path in your client's configuration.

Example client configuration
{
  "mcpServers": {
    "runui": {
      "command": "/Users/you/.local/bin/runui",
      "args": ["mcp", "-C", "/Users/you/projects/atlas"]
    }
  }
}

MCP clients use different configuration file names and shapes; use these command and argument values in your client's MCP server settings. Use command -v runui to find the binary. Linux home folders commonly start with /home/you.

ToolWhat it does
list_commandsReturn a catalog page with exact commands/cwd, IDs, fingerprints and provenance. Optional query, limit (default 200, max 500), and offset; follow next_offset. complete and diagnostics explain limitations.
start_runStart a persistent supervised run from either catalog id with optional fingerprint and inputs, or raw command with optional directory. Optional name labels either form. Catalog preparation rejects stale definitions and preserves literal arguments. The Agents tab shows the client's name.
list_runsList runs across all folders, with an optional exact working directory filter.
get_runAccept id; return state, timestamps, exit_code, agent, output_file, and other metadata. State exited covers success and failure; check exit_code for the outcome.
read_outputRead the latest plain-text tail by id, with optional lines (100 by default, 1–500 allowed). Returns at most 64 KiB plus state and a truncated flag. Poll to follow a live run; calls return a tail, not an incremental cursor.
stop_runAsk the supervisor to stop the run's process group, then use get_run to see its final state.
Tool-call examples

These are the tools/call parameters after your client has initialized the connection. Copy the ID and fingerprint returned by list_commands.

Start a discovered script
{
  "name": "start_run",
  "arguments": {
    "id": "ID_FROM_LIST_COMMANDS",
    "fingerprint": "FINGERPRINT_FROM_LIST_COMMANDS",
    "name": "web preview"
  }
}
Follow the returned run ID
{
  "name": "read_output",
  "arguments": {
    "id": "RUN_ID_FROM_START_RUN",
    "lines": 100
  }
}

The agent name comes from initialize.clientInfo.name. Metadata keeps it in agent, alongside output_file, the path to the complete raw output file. Agent and TUI runs use the same store and supervisor; either interface can stop the same process. Commands execute through the shell in their selected directory.

Reading and reviewing are separate

MCP reads do not clear finished notices. View a result in the TUI or run runui status clear to dismiss them. The optional list_runs.directory filter matches one exact folder, while the TUI’s Here tab includes the selected project’s descendants.

11

YOUR DATA

Files and history

Favorites and run history live in ordinary files under your home directory. You can inspect, back up, or remove them yourself.

Favorites~/.config/runui/favorites.jsonor under $XDG_CONFIG_HOME
Runs, metadata & output~/.local/state/runui/runs/or under $XDG_STATE_HOME

A run's folder holds run.json, output.log, a lock held by its supervisor, and a status.seen marker after review. The lock tells Runui whether the run is still alive, even after the interface exits.

catalog-v1.json beside the run folders keeps up to 1,000 recent invocations for 180 days and 2,000 aggregate keys independently of output retention. Launches from TUI, CLI and MCP are deduplicated by run ID. It uses atomic writes, a separate writer lock and mode 0600; corrupt state is backed up before repair. Ordinary search does not read personal shell history. Reviewing output does not increase usage, and a palette covering output does not review it.

Keep what matters

Runui keeps recent completed runs so you can return to their output. The Runs panel lets you stop a live command or forget an ended one. Viewing a finished run’s output clears its completed or errored status count without deleting the history. Press 4 for successful and failed results from every folder; Log → All keeps the reviewed history. Starting a new run retains the 40 most recent previous ended attempts.
